# 中文语音（唤醒词 → 识别 → DeepSeek → 中文播报）与“有波形但不回应”的排查

适用：已安装的 Jarvis 2.0.4（macOS）。配套补丁见 [weather-dingtalk.md](weather-dingtalk.md)（同一个补丁包，一起安装）。
本文不含任何真实位置、公司内容、账号或密钥。

> **云端测试都是 mock 或合成语音，不等于 Mac 上的真实验收。** 麦克风、真人说话、Mac 扬声器、系统声音、定位授权都必须在你的 Mac 上验收（第 6 节）。

## 1. 为什么“麦克风有波形，但软件不回应”

波形（顶部「麦克风」条）是麦克风的原始电平，在唤醒和识别**之前**就画出来了，所以它动只说明麦克风有声音，不说明后面的链路正常。链路是：

`麦克风 → 回声消除 → 唤醒（关键词 / 文字确认）→ 语音识别 → 大脑（DeepSeek）→ 语音合成 → 扬声器`

读代码找到的几处“静默失败”，现在都改成**看得见的错误**：

| 环节 | 之前 | 现在 |
|---|---|---|
| 默认是英文模式 | 唤醒只认 “Hey Jarvis”；待机时的文字确认用**英文** Parakeet，中文“嗨，贾维斯”被转成英文乱码，直接丢弃，像是“听不见” | 有完整的中文语音模式（见第 2 节）；没唤醒的话会在顶部显示“听到：…（不含唤醒词“…”，没有响应）”和用了哪个识别器 |
| 播报 | 英文 Piper 会把中文字符全部删掉；回答是中文时**一个字都不念** | 中文模式用中文引擎；播报失败时回答仍显示在屏幕上，并提示“语音播报：…原因” |
| 播报线程异常 | 线程悄悄结束，引擎停在“正在说话”，之后听不进去 | 捕获异常，显示原因，恢复到“继续聆听” |
| 回答线程异常 | 停在“思考中” | 显示“大脑：回答时出错…”，并用语音/文字道歉 |
| 识别/唤醒异常 | 被当成“没有找到麦克风”，音频流每 5 秒重启一次 | 单独报“语音识别：…”（30 秒内不重复），不再误报麦克风 |
| 状态卡住 | 无 | 说话/思考状态无进展（30 秒 / 200 秒）自动复位并提示 |
| 大模型连不上 | 只说“连不上” | 带原因：密钥无效、网络超时、额度用完、模型名不对（不含密钥） |
| 引擎缺模型 | 服务启动失败，界面一直“等待语音服务” | 缺中文模型时自动用已装好的英文模式启动，并在「语言与语音」里写明缺什么 |

另外修了一个中文模式下的真实 bug：“嗨，贾维斯，今天天气怎么样”一口气说完，命令会丢掉开头几个字（变成“天气怎么样”），原因是为“英文唤醒词+中文命令”写的重新识别逻辑也在中文模式下执行；现在只在英文模式执行。

**我没有复现你那台 Mac 上的真实情况**（你在并行做本机诊断）。按可能性排序：英文模式下说中文（最可能）→ 播报引擎问题 → 声纹只认你的声音 → 麦克风/权限。诊断时看顶部的提示条、「语言与语音」面板，以及 `~/.jarvis/voice.log` 里这些行：
`mic peak … | wake best …`（每 10 秒一行，麦克风是否有声、唤醒分数）、`heard (standby): …`（识别出了什么）、`wake check: … -> yes/no`、`ignored (not your voice)`、`event command`、`reply: …`、`speech failed: …`、`engine failed:`。

## 2. 中文语音模式

在「菜单 → 语言与语音」里点「中文语音」，或安装补丁时加 `--zh`。切换后：

| 环节 | 中文模式用什么 | 在哪里运行 |
|---|---|---|
| 唤醒 | sherpa-onnx 关键词识别（wenetspeech KWS，“嗨/嘿贾维斯”）+ 识别文字确认；英文 “Hey Jarvis” 在中文模式走 SenseVoice 文字确认（含 JERVIOUS 等窄别名），**不必**切 `voice_lang=en`。不叠 openWakeWord 声学（会对中文「贾维斯」误触发） | 本机离线 |
| 识别 | SenseVoice（中/英/日/韩/粤）。**不用** Parakeet；openWakeWord 仍属英文模式声学唤醒 | 本机离线 |
| 大脑 | 你在「接入大脑」里选的模型（如 DeepSeek），只发送识别出的文字和工具结果；系统提示词、错误提示、日程/提醒/全息解说全部用中文 | 云端（仅文字） |
| 播报 | **Kokoro 多语言 v1.1**（sherpa-onnx 官方发布的开源模型，中英混读）；没装时可用 **macOS 系统中文声音**（Tingting 等，`say`） | 本机离线 |

- **播报引擎和语言始终显示**在「语言与语音」面板里（例如“Kokoro 多语言 v1.1（本机离线）（中文）”或“macOS 系统声音「Tingting」（本机）（中文）”）。没有任何引擎可用时显示原因，回答只显示文字，不会静默。
- **不会把语音送给第三方**：识别、唤醒、合成都在本机；macOS `say` 只用本地声音，不是 Siri 云端。只有文字发给你选的大模型。
- 中文播报引擎可选：自动（优先本机模型，没有则用系统声音）/ 本机 Kokoro / macOS 系统声音；显式选择不会被悄悄换成别的引擎。「试听一句」按钮直接测试播报链路。
- 切换时服务**总是**先调用安装器：缺的模型会下载，已经在磁盘上的模型文件夹也会逐文件核对（见第 3 节），**核对通过才改语言**；压缩包先核对大小和 sha256（中文唤醒模型 32 MB、Kokoro 365 MB，校验值写在清单里），不通过就拒绝安装、不切换；成功后语音服务自己重启，窗口自动重连。
- 回答语言跟随语音语言（`reply_lang` 默认随 `voice_lang`）。**用英文 “Hey Jarvis” 唤醒不会把回答改成英文**：字幕、TTS、大脑提示词仍按 `reply_lang`（中文模式即为中文）。不要靠切 `voice_lang=en` 来开英文唤醒。
- SenseVoice 常把 Jarvis 听成 `JERVIOUS` / `JARVIOUS` 等：文字确认里有一份**窄**别名表（只覆盖这类近音，不会把 `service` / `travis` / `jealous` 当成唤醒）。
- 声纹录入的句子在中文模式下全是中文。

配置（`~/.jarvis/config.json`）：`voice_lang`: `zh`/`en`，`reply_lang`，`voice_tts`: `auto`/`local`/`system`，`system_voice`: `say -v ?` 里的名字。

**已用真实本地模型验证（云端 Linux）**：`tests/test_voice_zh.py` 用 Kokoro 生成中文语音，再喂给真实的唤醒+识别链路：中文模式确实走 KWS + SenseVoice（Parakeet 未加载）；“嗨，贾维斯，今天天气怎么样”“把客厅的灯打开”“现在几点了”都得到完整命令；没有唤醒词的话只显示“听到…”、不执行；Kokoro 逐句输出中文音频。这证明模型和路由没问题，**不是**真人声音和 Mac 麦克风的测试。

## 3. 关于 CI 里 Parakeet 校验失败（已查明，不是网络问题）

`sherpa-onnx-nemo-parakeet-tdt-0.6b-v2-int8` 在 Hugging Face 的 `main` 分支被重新导出过（encoder 652282309 字节，sha256 `92a10bd9…`），和清单里登记的版本（652184296 字节，`a32b12d1…`）不同。官方锁定的 revision `1ab9323565ddb038682214b292f588070a538ce2` 的 encoder 正是登记的那一版：已用 Hugging Face 返回的 LFS sha256 核对四个文件（encoder / decoder / joiner / tokens）与清单逐一一致，encoder 另外完整下载后自己算了 sha256。所以：

- `app/models.json` 里 Parakeet 四个文件的下载地址改成固定到该 revision（hf-mirror 和 huggingface 两个来源），**校验值没有改、也没有跳过校验**；
- GitHub 上的 tar.bz2 兜底来源是“当前版本”，校验不会通过，仍然会被拒绝；
- 新增：`dirs`（中文唤醒、Kokoro）的压缩包核对大小和 sha256（Kokoro 的值与 GitHub 发布页的 digest 一致；唤醒模型的 sha256 是我下载官方文件后算出来的，首次固定），并且**已经在磁盘上的文件夹也要通过逐文件校验**：`app/models.json` 里记录了官方压缩包解开后每个文件的大小和 sha256（用 `tools/dir_manifest.py` 从已校验的压缩包生成，唤醒 25 个文件、Kokoro 377 个文件）。文件夹必须和清单**完全一致**（缺文件、大小或校验值不对、符号链接、多出的文件都算不一致；Finder 的 `.DS_Store` 除外）。不一致（包括旧安装器留下的、没校验过的、下到一半的文件夹）就从官方压缩包重新下载，压缩包先过 sha256 再逐文件核对，通过后才原子替换；任何一步失败都不动原来的文件夹。「语言与语音」里的切换也走同一个检查，不会因为“文件夹已经在”就信任它。

## 5. 安装、回滚

和天气/钉钉是同一个补丁包（`jarvis-2.0.4-zh-weather-dws-patch.tar.gz`），步骤见 [weather-dingtalk.md](weather-dingtalk.md) 第 5 节：

```bash
./install.sh --dry-run
./install.sh --zh --dws "<你的 dws 绝对路径>"     # --zh 现在下载中文模型并切到中文；不要中文/钉钉就去掉对应参数
./rollback.sh --clean-config                       # 还原文件，并把 voice_lang / reply_lang / dingtalk 等配置还原
```

- `--zh`：**先**逐文件验证（已有的文件夹也验证，不一致就从官方压缩包重下），**通过后**才改 App 文件、才写入 `voice_lang/reply_lang = zh`；验证失败：App、`voice_lang`、`reply_lang` 一个都不动，脚本报错退出。你机器上旧安装器留下的“`voice_lang=zh`、`reply_lang` 未设、中文文件夹没校验过”的状态，会在这一步被验证后才补上 `reply_lang`。
- 全程是事务式的：复制文件失败会把已改的文件还原；配置最后才写、一次原子替换，读不出 JSON 的配置不会被覆盖。
- 回滚（`rollback.sh --clean-config`）把 `voice_lang`、`reply_lang`、`dingtalk` 恢复成**第一次运行 install.sh 时**的值。以上面的状态为例：`voice_lang` 仍是 `zh`（旧安装器留下的中间状态），`reply_lang` 被删掉；**不会**自动恢复你更早的备份，也不会改动或删除任何备份文件夹。
- 回滚不会删除已下载的模型（没有害处，也省得重下）。
- DeepSeek 配置、API key、记忆、声纹、已授予的权限都不动；`config.json` 只合并几个键并保持 600 权限。

## 6. Mac 验收清单（中文语音；音色和启动见第 7、8 节的补充项）

1. 装补丁（`--zh`）后打开 Jarvis。顶部/状态栏应写「嗨，贾维斯 / Hey Jarvis」；「菜单 → 语言与语音」里：语音语言“中文（回答：中文）”、识别 SenseVoice、播报引擎名称和“（中文）”。
2. 点「试听一句」：应听到中文播报；听不到时顶部提示条会写原因（引擎缺失/合成出错）。
3. 说“嗨，贾维斯”，等“我在”，再说“今天天气怎么样”：应听到中文回答，字幕是中文；「语言与语音」里“最近一次用：SenseVoice”。
3b. 说 “Hey Jarvis”（或 SenseVoice 听成 JERVIOUS 时仍应唤醒），接着中文命令：回答/字幕/播报仍是中文；`voice_lang` 仍是 `zh`，不要被切成 `en`。
3c. 随便说含 service / travis / “今天天气不错…” 且无唤醒词：不应唤醒。
4. 不说唤醒词直接说一句话：顶部应显示“听到：…（不含唤醒词，没有响应）”。
5. 把「中文播报引擎」切到“macOS 系统声音”再试听：应是系统中文声音，面板里标明。
6. 在「接入大脑」里把密钥改错再提问：应听到/看到“连不上语言模型：密钥无效…”。
7. 切回 English voice 再切回中文，确认能恢复；`ls ~/.jarvis/run/` 为空。
8. 如果仍然“有波形不回应”：打开面板截图、`~/.jarvis/voice.log` 里 `mic peak`、`heard`、`wake check`、`speech failed`、`engine failed` 附近的行（先去掉其中的听写内容再发）。

## 7. 中文男声选择与机械效果（可选、可恢复）

**状态：代码和合成样本已测试；声音是否合你的意，要你自己听，你确认之前不能算解决。**

「菜单 → 语言与语音」里（播报引擎是本机 Kokoro 时）多了两项设置：

| 设置 | 内容 | 默认 |
|---|---|---|
| 中文男声 | 模型自带的 45 个中文男声（`zm_009` … `zm_100`，sid 58–102），列表里写着名字、sid 和**实测基频**（同一句话的基频中位数，只供选深沉/偏亮时参考） | `zm_029`（sid 68） |
| 机械效果 | 单独的开关：「轻回声（默认）」/「机械（金属感）」/「关闭」，加一个 0–100% 的强度滑块 | 轻回声 100%（和以前完全一样） |

按钮：「试听（不保存）」用你当前选的声音和效果念一句固定的话，什么都不保存；「使用这个声音」保存并试听；「恢复默认」删掉这两项设置，回到 zm_029 + 轻回声。设置存在 `~/.jarvis/config.json` 的 `voice_speaker`（整数）和 `voice_fx`（`{"mode": "scifi|robot|off", "amount": 0~1}`）；没有这两项就是旧行为，输出和以前逐位一致（有测试）。`rollback.sh --clean-config` 也会删掉它们。

**说话人表是真实的，没有编造**：来自 sherpa-onnx 官方文档里 kokoro-multi-lang-v1_1 的编号表（103 个说话人：af/bf 英文女声 sid 0–2，zf 中文女声 sid 3–57，**zm 中文男声 sid 58–102**），和模型文件对得上（`voices.bin` 恰好是 103 × 510 × 256 个 float32，测试里校验）。代码只接受这 45 个编号，女声、越界编号、乱填的值一律回退到默认。

**效果**：「机械」是 `robot()`：环形调制（70 Hz 载波，经典机器人声）+ 6 ms 短共振梳状滤波，再带通到 150–7000 Hz、软限幅，输出峰值固定在 0.9，**不会削波**；它改变音色，**不改变语速和内容，也不是用降速冒充换声线**（语速始终 1.0，换声线只靠换说话人）。强度 0 等于无效果。耗时：约 16 ms / 6 秒语音（轻回声约 2 ms），句子级处理，不增加可感知延迟。系统声音（macOS `say`）默认不加效果，只有你设置过效果才加。

**用真实模型做过的客观检查**（`tests/test_voice_zh.py`）：4 个男声 × 4 种效果，经本机识别回读都和原句一致到至多错一两个字（普通话清晰）；峰值 ≤ 0.9；不同说话人的波形确实不同；机械效果确实改变波形。**这些检查证明“清晰、没削波、确实不同”，不证明“好听”或“够机械”。**

## 8. 启动与退出：旧语音服务占着 8765

**问题**：窗口关了不等于上一次的语音服务退出了（崩溃、强制退出、重启时恰在运行）。旧的 `python -m jarvis` 还占着 8765 时，新服务绑定端口失败，新窗口要么没有语音服务，要么悄悄接上一个旧版本的服务。

**修复（最小）**：
- 新服务启动时如果端口被占：只会停掉**同一用户**的、命令行是 `python -m jarvis` 的旧语音服务（先 SIGTERM，等 5 秒，不行再 kill），然后正常绑定；pid 来自 `~/.jarvis/voice.pid` 和监听该端口的进程。**占着端口的是别的程序就不碰它**，直接在日志里写明是哪个进程，服务以明确的错误退出，而不是静默失败。
- 服务启动后写 `~/.jarvis/voice.pid`，正常退出时删除；pid 文件过期或指向不存在的进程都无害。
- 窗口退出时终止它启动的服务后，再 `wait` 回收，确保不会遗留。
- 窗口退出本身仍然不被当作“服务一定退出”：服务自己的“20 秒没有窗口就退出”保留，新服务启动时的接管是兜底。

测试：`tests/test_service_port.py`（用假的 `python -m jarvis` 进程）覆盖：端口空闲、有 pid 文件的旧服务被停、没有 pid 文件时通过监听端口找到并停掉、**其他程序占端口不被碰**、过期 pid 文件无害。

## 9. 在已安装的 af405c6 上叠加升级

升级包只含 af405c6 之后改动的文件（`jarvis-2.0.4-upgrade-af405c6-to-<新提交>.tar.gz`），`install.sh` 接受的“旧版本”就是 af405c6 安装后的文件，**不需要 `--force`**；它还会核对上一个补丁的其余文件都在原位，对原版 2.0.4 或被改过的文件会明确拒绝（不会只装一半）。用法同第 5 节：

```bash
tar xzf jarvis-2.0.4-upgrade-af405c6-to-<新提交>.tar.gz && cd jarvis-2.0.4-upgrade-af405c6-to-<新提交>
./install.sh --dry-run          # 只检查
./install.sh                    # 先退出 Jarvis；不要再带 --zh / --dws（已经装过，配置不动）
```

- 备份是新的目录（旧备份不改写），里面是升级前（af405c6）的文件。要只撤销这次升级：`./rollback.sh --backup "<那个备份目录>"`；不带 `--backup` 的 `./rollback.sh` 会把所有备份依次还原，最终回到官方 2.0.4。
- 声音设置（`voice_speaker`、`voice_fx`）不在安装里写，只在你点「使用这个声音」时保存，随时「恢复默认」。

### 第 7、8 节的 Mac 验收项
1. 「语言与语音」里出现“中文男声”和“机械效果”；先听三个样本文件，再用同样的说话人和效果在面板里「试听（不保存）」，应和样本一致。
2. 选 `zm_098` + 关闭效果 / `zm_014` + 机械 100%：回答应该是中文男声，机械那个明显是机器人质感，普通话仍然听得清。不满意就换说话人或调强度；还是不满意请告诉我具体哪里不对（偏高、太糊、不够机械、太吵……）。
3. 「使用这个声音」后重启 Jarvis，声音保持；「恢复默认」后回到 zm_029 + 轻回声。
4. 连续快速退出再打开 Jarvis（甚至强制退出后立刻重开）：窗口应该能连上语音服务，`~/.jarvis/voice.log` 里可能有一行 “older Jarvis voice service … stopping it”，没有 “bind” 报错；`ps aux | grep "jarvis"` 只有一个语音服务进程。
